# Kuroba Sequencing Auditor — 2026-03-31

## Key Challenge (one sentence)
Kuroba-first is a learning-theater deployment that validates nothing about Alizé's ICP, delays actual external validation by weeks, and functions as the most sophisticated deferral mechanism in a debate log already overflowing with deferral mechanisms.

## Assumptions Challenged

### Assumption 1: "Kuroba's 2-3 person scale is a valid proxy for Alizé's ICP of 50-200 employee service firms"

**D106 already flagged the scale mismatch — but the full implications were not absorbed.**

The gap between a 2-3 person agency and a 50-200 person PME is not a scaling problem. It is a categorical difference:

| Dimension | Kuroba (2-3 people) | ICP Target (50-200 employees) |
|-----------|---------------------|-------------------------------|
| Decision-maker | One co-founder, same room | DG + Head of Ops + IT, multiple stakeholders |
| Procurement | "Let's do this." | Formal vendor process, legal review, IT sign-off |
| Budget authority | Co-founder discretionary | Board-level or CFO-level approval |
| Technical stack | Simple, modern, Louis knows it | Legacy systems, multiple tools, no single owner |
| Implementation friction | Near-zero (shared ownership) | Real (multiple departments, change resistance) |
| Negotiation dynamics | None (co-founders) | Full stakeholder management required |
| Delivery feedback | Filtered by personal relationship | Market-raw and honest |

**The core problem:** Louis cannot credibly practice client-facing delivery with his own co-founders because the adversarial dynamics that make delivery hard simply don't exist in that relationship. When Maëli pushes back on a deliverable, it's a conversation between friends. When a DG at a 100-person firm pushes back, it's a professional negotiation that can end the engagement. These are fundamentally different skills. Kuroba does not develop the second skill set — it develops the illusion of having developed it.

**D106's verdict (from the debate log) was correct but underweighted:** "Scale mismatch invalidates rehearsal proxy. 2-3 person agency ≠ 50-200 person PME deployment complexity." This decision should have ended Kuroba-first as a strategy. It did not.

---

### Assumption 2: "Kuroba-first is a genuine learning path, not another deferral dressed up as action"

**Kuroba has been 'imminent' for 18+ pulses. It has never happened. The pattern is diagnostic.**

The sequence is always the same:
1. Kuroba deployment becomes "ready to proceed"
2. A new prerequisite emerges ("but first we need X")
3. Kuroba gets deferred as a prerequisite
4. The prerequisite resolves
5. Kuroba is reinstated as "parallel"
6. Something else becomes a prerequisite
7. Return to step 1

This is the pulse equivalent of "I'll start my diet on Monday." Except the version where Monday never arrives has been running for 18+ cycles.

**Why Kuroba specifically functions as a deferral mechanism:**
- It lives inside Louis's network — no external credibility to lose by delaying
- It requires Gabin to finish a landing page — a convenient external dependency Louis cannot control
- It can always claim to be "still learning" without ever being tested against market reality
- Every pulse that passes without an external client validates the Kuroba cycle: "we're still preparing"

**The opportunity cost is concrete:** If Kuroba-first consumes Month 1 (4 weeks, per D102), then the first external validation signal arrives in Month 2 at earliest. If the first warm outreach to Louis's actual network (D26, D120) happens in Month 1 alongside Kuroba preparation, external validation could arrive in weeks — not months.

**Kuroba-first is not "parallel" to real outreach. It is blocking it.** Every hour spent preparing Kuroba's rehearsal is an hour not spent on outreach that produces market-validated signals.

### Assumption 3 (Bonus): "Kuroba's playbook knowledge is safe to develop and retain"

**D105 raised the knowledge transfer risk but stopped short of the full implication.**

D105: "If web agency used, playbook must exclude transferable competitive knowledge."

This is unworkable. A delivery playbook that excludes competitive knowledge is a playbook that excludes the valuable parts. Maëli and Gabin have full visibility into Alizé's strategy. Developing a playbook on Kuroba's infrastructure and then trying to sanitize it before deploying to external clients is an accounting fiction, not a competitive strategy.

## Findings

**Finding 1:** Kuroba's deployment complexity is categorically incomparable to the ICP. Louis cannot develop client-facing delivery skills in a co-founder relationship. The rehearsal produces the illusion of preparation, not the capability.

**Finding 2:** Kuroba has been "imminent" for 18+ pulses without executing once. The pattern is structurally identical to every other deferral mechanism in this debate log. The word "prerequisite" has become a flag that means "this will be used to delay the real action."

**Finding 3:** The debate log already contains the correct alternative: D26 (warm network as primary channel) and D118 (Month 1 warm outreach starts immediately). The research already identified that Louis's warm network is the fastest path to external validation. Kuroba-first directly competes with this path for Louis's limited hours.

**Finding 4:** D187 (mentioned in the task brief, "D187 killed 'using Grinto relationships'") conflicts with the actual decision record. D119 explicitly states: "Grinto ring-fencing — Explore in Week 1; if viable, removes delay." The Grinto path was not killed — it was ring-fenced and flagged for Week 1 resolution. That Week 1 resolution apparently never happened, which means the deferral of Grinto outreach and the deferral of Kuroba are both part of the same avoidance pattern.

**Finding 5:** The Kuroba landing page (Gabin's responsibility) has been a blocker for months. Relying on an external dependency to unblock your first deployment is not a strategy — it is an excuse that lets Louis remain in research mode while waiting for someone else to act.

---

## Recommendation

**Kill Kuroba-first as a sequencing strategy. Now.**

Specifically:

1. **Do not use Kuroba as Month 1's primary deployment target.** The scale mismatch is categorical, not incremental. It will not produce transferable learning.

2. **Redirect Month 1 energy to warm network outreach immediately.** D26 and D118 are live decisions: warm outreach starts Month 1 with narrow ICP (top 10-15 contacts). Execute this instead of preparing Kuroba.

3. **If a delivery rehearsal is genuinely needed, do it via peer roleplay.** D122 confirmed: simulated delivery rehearsal (peer roleplay), NOT live client delivery. Do this internally. Do not use a client relationship — real or internal — as the rehearsal vehicle until the rehearsal skills are developed.

4. **Resolve Grinto ring-fencing in Week 1, as D119 intended.** D119 exists. It has not been executed. U116 ("Grinto ring-fencing feasibility — Does Grinto contract allow side venture?") is still unresolved. Resolve it. If Grinto allows side ventures with ring-fencing, start the outreach immediately. If it doesn't, know that now and stop using it as a mental placeholder for "outreach I'm not doing yet."

5. **The only thing Kuroba-first is actually good for is delaying external validation.** Every week spent on Kuroba rehearsal is a week without a market signal. The 3-6 month effective window (D82) does not wait. Either execute the external pilot or admit the window is already being consumed by preparation theater.
