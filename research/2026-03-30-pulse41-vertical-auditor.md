## Challenge 1: Category Confusion — Louis Is Simultaneously a Web Agency Co-Founder and an AI Agent Company

### The Structural Problem

D206's vertical (e-commerce operations via Grinto referrals) requires Louis to:
1. **Co-found a web agency** (Kuroba, with Maëli and Gabin) — D194/D195 confirmed this as the Month 1 internal deployment
2. **Intern at a web agency** (Grinto)
3. **Found an AI agent company** (Alizé) targeting e-commerce companies

The three roles are not separate. They are the same person, same context, same market.

**The category confusion this creates:**

| Role | What Louis Does | Who He's Selling To |
|------|-----------------|---------------------|
| Kuroba co-founder | Building websites for e-commerce companies | E-commerce companies |
| Grinto intern | Web development at a Caen agency | E-commerce companies (Grinto's clients) |
| Alizé founder | AI agents for e-commerce operations | E-commerce companies |

Louis is selling competing services into the same market through three different channels simultaneously. An e-commerce company that becomes a Kuroba client is simultaneously a prospect for Alizé. A Grinto e-commerce client is simultaneously being introduced to Louis-as-Alizé-founder through the referral network.

**The perceptual problem for e-commerce clients:**

When an e-commerce company gets a Grinto referral to Alizé, their internal question is: "Is this the web developer who built our site trying to sell us AI services now?" 

The answer is often "yes" — and this is a problem because:
- E-commerce companies that use Grinto for web dev already have a vendor relationship
- That vendor is now referring them to another Louis-company for more services
- The client may wonder: is this one company with two offerings, or two competing companies?
- If they perceive Louis as their web developer first, Alizé's positioning as an AI agent specialist loses credibility

**The Kuroba contradiction:**

D194/D195 says Kuroba is the internal deployment target — "we built it for ourselves first." This is presented as a strength. But Kuroba is a web agency. If Kuroba is the internal deployment:
- Kuroba tests Alizé's AI agent capabilities on web agency workflows
- But D206 says the first vertical is e-commerce operations (order processing, inventory sync, customer service)
- These are NOT web agency workflows. Kuroba does not do order processing or inventory sync for its clients.
- The internal deployment is testing the wrong workflows for the claimed vertical.

**This is a category mismatch between the internal deployment and the external vertical.**

### Verdict on Challenge 1

**Louis's three roles (Kuroba co-founder, Grinto intern, Alizé founder) create a category confusion problem that D206 does not address.** An e-commerce company referred by Grinto will see Louis as their web developer, not as an AI agent specialist. The internal deployment (Kuroba) tests web agency workflows, not e-commerce operations workflows. D206's vertical requires Louis to be three different things to the same market simultaneously.

## Challenge 3: The Grinto Referral Network Is a Web Development Network, Not an AI Agent Network

### What Is a Warm Referral Network?

A warm referral network for a service business means: people who know you, trust you, and will introduce you to potential clients who trust them. The trust transfer is the value of the warm referral.

**The Grinto referral network is optimized for web development trust, not AI agent trust.**

Grinto is a Caen web agency. Its clients hired Grinto because:
- They needed a website built or redesigned
- They needed web development expertise
- They needed a local or trusted vendor for digital projects

The trust that Grinto's clients have in Grinto is specific to web development services. When Grinto refers a client to Alizé, the referral carries an implicit message: "This is someone we trust for a different type of service."

**The problem:** AI agents for e-commerce operations (order processing, inventory sync, customer service) are categorically different from web development. The trust transfer is not natural. Grinto's clients trust Grinto to build websites — not to vet AI automation vendors for operational workflows.

### The Referral Type Mismatch

| Referral Type | What It Signals | Effective For |
|---------------|-----------------|----------------|
| "I used this person for X, they were great" | Competence + reliability | Same service category |
| "I know this person, they're honest and capable" | Character trust | New service category |
| "My web developer recommends this AI vendor" | Category mismatch | Weak — no domain connection |

The Grinto referral to Alizé is the third type: a web developer recommending an AI vendor. The referrer has no domain credibility in the referred service category. This is weaker than a warm referral in the same category.

**D206 treats "Grinto referral network" as a monolithic warm network.** It is not. It is a warm network for web development services that is being asked to produce warm referrals for AI agent services — a different category with different trust requirements.

### What Makes a Referral Warm for AI Agents?

For an AI agent company, a warm referral means:
- The referrer has seen the AI agent work
- The referrer understands what AI agents do and can articulate the value
- The referrer can identify which of their contacts have the specific problem the AI agent solves

Grinto (a web agency) can provide:
- Warm contacts with e-commerce companies
- But not warm contacts who understand AI agent value
- And not warm contacts identified specifically for e-commerce ops workflows

**The Grinto referral network yields contacts, not qualified prospects.** The qualification work still needs to happen. D206's conditional conflates "warm contact" with "qualified prospect." They are not the same thing.

### Verdict on Challenge 3

**The Grinto referral network is a warm network for web development services, not AI agent services.** Using it as the access mechanism for e-commerce AI agents requires an extra trust-building step (explaining why a web developer is recommending an AI company). This reduces conversion probability compared to a referral from a source with AI domain credibility.

## Bonus Challenge: E-Commerce Operations Workflows May Not Be Deliverable at Month 1

### The Delivery Capability Question

D206 names "e-commerce operations" as the vertical. The implied workflows are:
- Order processing (across Shopify, WooCommerce, Amazon, Cdiscount)
- Inventory synchronization
- Customer service triage
- Reporting aggregation

**Are these within Alizé's demonstrated delivery capability at Month 1?**

Kuroba (the internal deployment) is a web agency. Its workflows are:
- Project management for web development
- Client communication
- Document sharing
- Internal coordination

**Kuroba does not do order processing, inventory management, or customer service.** The internal deployment (D194/D195: "we built it for ourselves first") is testing the wrong workflows for the vertical it supposedly enables.

### What Alizé Can Actually Demonstrate at Month 1

The Kuroba internal deployment will produce demonstrations of:
- Web agency workflows (project status updates, client onboarding, meeting notes)
- NOT e-commerce operations workflows

An e-commerce prospect asking "show me how your agent handles order processing across Shopify and Amazon" will see a demo built for a web agency's internal operations. The proof point does not match the vertical claim.

### The Technical Complexity of E-Commerce Operations

E-commerce operations automation is technically complex:
- **Multi-platform API integrations** (Shopify, WooCommerce, Amazon Seller Central, Cdiscount, Mirakl)
- **Real-time inventory synchronization** across platforms with conflict resolution
- **Order processing** requires webhook handling, status updates, cancellation flows
- **Customer service** requires email/chat integration, CRM connectivity, escalation logic

These are not "prompt engineering" problems. They require:
- Platform-specific API knowledge
- Error handling and retry logic
- Data mapping between systems
- Ongoing maintenance as platform APIs change

**If Alizé's Month 1 deliverable is a working agent doing e-commerce operations (per D206's vertical), but the internal deployment is Kuroba (web agency workflows), there is a delivery credibility gap.**

### Verdict on Bonus Challenge

**The e-commerce operations workflows D206 implies are not validated by the internal deployment (Kuroba).** The internal deployment tests web agency workflows. The external vertical requires e-commerce operations workflows. These are different technical domains. Alizé would be selling e-commerce operations automation before demonstrating it internally.
